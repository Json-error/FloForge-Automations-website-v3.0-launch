## Posting strategy

1. Post one strong launch message rather than spamming the same link repeatedly.
2. Lead with the problem and a concrete feature, not a generic "check out my project" message.
3. Use the clean product screenshot showing the strongest workflow/automation concept.
4. Reply to genuine questions and criticism with technical details.
5. Do not ask strangers to star the repository without first giving them a reason to care.
6. Do not mass-comment links on unrelated repositories or communities.
7. Track referral traffic and GitHub views after each legitimate post.

## Best screenshot order

1. Landing page hero showing the workflow concept.
2. Overview dashboard.
3. Automation Center with a populated demo automation.
4. Integrations.
5. Billing.

## 24-hour target

A realistic first objective is **20–100 qualified repository visits**, not a specific number of stars. A smaller number of developers who actually inspect the code is more valuable than hundreds of empty clicks.

## What success looks like

- Visitors open the README instead of bouncing immediately.
- Visitors click the live demo.
- Developers inspect source files.
- Someone opens an issue with useful feedback.
- Stars and forks happen naturally after people understand the project.

Do not manufacture any of these signals.
